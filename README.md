# Production Files Integration API (Simulation)
 
[English](#english) | [Português](#português)
 
## English
 
A .NET 8 Web API that simulates receiving production file links from an integration platform (iPaaS), with idempotent processing and notification reprocessing.
 
### Tech stack
 
- .NET 8 and ASP.NET Core Web API
- Entity Framework Core with SQLite
- xUnit
- Swagger
### Getting started
 
Prerequisite: .NET 8 SDK (the version is pinned in `global.json`).
 
```
dotnet run --project ApiFoundation.Api
```
 
Swagger is available at `/swagger`, using the URL shown in the terminal.
 
The SQLite database (`app.db`) is created and seeded with orders 1007, 1008 and 1012 at startup. To recreate it, stop the API and delete the `app.db*` files.
 
### Running the tests
 
```
dotnet test
```
 
### Endpoints
 
| Method | Route | Description |
| --- | --- | --- |
| `POST` | `/api/arquivos-producao` | Receives the file links for one or more services. |
| `GET` | `/api/pedidos/{pedidoSVL}` | Returns the order, its links and the notification status. |
| `POST` | `/api/notificacoes/reprocessar` | Simulates the worker that retries `PENDENTE` (pending) notifications. |
 
### Simulating a notification failure
 
In `appsettings.json`, set the option below and restart the API:
 
```json
"LeomobFake": { "FalharSempre": true }
```
 
### Design decisions
 
- `PedidoSVL` is the order's primary key. It comes from the source system and is not generated by the database.
- `hasErrors = true` rejects the entire request with **422**.
- A missing order or a mismatched `serviceId` fails only that service. The response lists the result of each service: `Processado` (processed), `JaProcessado` (already processed) or `Falha` (failed).
- Processing is idempotent. Only links not yet stored (same category and URL) are saved and copied.
- If there are no new links, the result is `JaProcessado` and nothing is duplicated, including the notification.
- If the same service arrives with different links, the new links are added.
- `Tentativas` counts failed attempts. After 3 failures, the notification status changes to `FALHA` (failed).
- The SQLite database is created with `EnsureCreated()`, without migrations.
- File storage and the notification service are fake implementations behind interfaces.
### Future improvements
 
- Save the links and the `INICIAL` (initial) notification in the same transaction. Today, if the process stops between the two steps, the notification is lost.
- Add migrations and a unique index on `LinkArquivo (PedidoSVL, Categoria, Url)` to protect against concurrent requests.
- Add automatic reprocessing with `BackgroundService` and structured logs that include `pedidoSVL`.
- Add real storage and notification service implementations, with timeouts and a retry policy.

## Português
 
API em .NET 8 que simula o recebimento de links de arquivos de produção vindos de uma plataforma de integração (iPaaS), com processamento idempotente e reprocessamento de notificações.
 
### Tecnologias
 
- .NET 8 e ASP.NET Core Web API
- Entity Framework Core com SQLite
- xUnit
- Swagger
### Como rodar
 
Pré-requisito: SDK do .NET 8 (o `global.json` fixa a versão).
 
```
dotnet run --project ApiFoundation.Api
```
 
O Swagger fica em `/swagger`, na URL que o terminal mostrar.
 
O banco SQLite (`app.db`) é criado e populado com os pedidos 1007, 1008 e 1012 ao subir. Para recriar o banco, pare a API e apague os arquivos `app.db*`.
 
### Como rodar os testes
 
```
dotnet test
```
 
### Endpoints
 
| Método | Rota | Descrição |
| --- | --- | --- |
| `POST` | `/api/arquivos-producao` | Recebe os links de um ou mais serviços. |
| `GET` | `/api/pedidos/{pedidoSVL}` | Retorna o pedido, os links e o status da notificação. |
| `POST` | `/api/notificacoes/reprocessar` | Simula o worker que tenta de novo as notificações `PENDENTE`. |
 
### Como simular falha na notificação
 
Em `appsettings.json`, defina a opção abaixo e reinicie a API:
 
```json
"LeomobFake": { "FalharSempre": true }
```
 
### Decisões de projeto
 
- `PedidoSVL` é a chave primária do pedido. Vem do sistema de origem e não é gerado pelo banco.
- `hasErrors = true` rejeita o envio inteiro com **422**.
- Pedido inexistente ou `serviceId` divergente falham só aquele serviço. A resposta lista o resultado de cada um: `Processado`, `JaProcessado` ou `Falha`.
- O processamento é idempotente. Só links ainda não salvos (mesma categoria e URL) são gravados e copiados.
- Se não houver nenhum link novo, o resultado é `JaProcessado` e nada é duplicado, nem a notificação.
- Se o mesmo serviço chegar com links diferentes, os novos são adicionados.
- `Tentativas` conta as tentativas que falharam. Ao chegar em 3, a notificação vai para `FALHA`.
- O banco SQLite é criado com `EnsureCreated()`, sem migrations.
- O armazenamento de arquivos e o serviço de notificação são implementações falsas atrás de interfaces.
### Melhorias futuras
 
- Gravar os links e a notificação `INICIAL` na mesma transação. Hoje, se o processo cair entre os dois passos, a notificação se perde.
- Adicionar migrations e um índice único em `LinkArquivo (PedidoSVL, Categoria, Url)` para proteger contra envios simultâneos.
- Adicionar reprocessamento automático com `BackgroundService` e logs estruturados com o `pedidoSVL`.
- Adicionar implementações reais de armazenamento e do serviço de notificação, com timeout e política de retentativa.
